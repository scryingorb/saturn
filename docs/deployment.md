# Deployment

Saturn has two production targets sharing the same dashboard:

| Target | Build | Output | API |
| --- | --- | --- | --- |
| GitHub Pages | `pnpm build:pages` | `pages-dist/` | Built-in encouragement by default; optional Cloudflare URL |
| Cloudflare Workers | `pnpm build` | `dist/client/` and `dist/server/` | Same-origin `/api/affirmation` |

## GitHub Pages

The site URL is **https://scryingorb.github.io/saturn/**. The repository's Pages publishing source must be **GitHub Actions**. `.github/workflows/pages.yml` tests and builds both targets, checks the Worker deployment package, inspects the static bundle, and publishes Pages on pushes to `main`. Pull requests validate without publishing.

The default base path is `/saturn/`; assets and the favicon use this path. Set `PAGES_BASE_PATH=/` for a custom domain or a user site, and update the workflow accordingly. The Pages artifact contains static files only. Do not upload `dist/server/` to Pages.

Optional AI: after deploying the Cloudflare Worker, add the repository **Actions variable** `SATURN_AFFIRMATION_URL` with the public URL `https://<your-worker-host>/api/affirmation`, then rerun the Pages workflow. This variable is a public URL, never an API key. Until it is configured, the Magic 8 Ball gives labeled built-in encouragement without calling a nonexistent Pages API.

Weather talks directly to the keyless Open-Meteo API. Tasks and mood use local storage on the current origin. Data from localhost or the previous GitHub owner domain does not automatically migrate to the published origin.

## Cloudflare Workers

`wrangler.json` names the Worker `saturn`, allows the Pages origin `https://scryingorb.github.io`, and configures a 10-request-per-minute per-IP AI limiter. If the Pages domain changes, update `AFFIRMATION_ALLOWED_ORIGINS` (comma-separated exact origins) and rebuild. CORS controls browser access; it is not authentication. The limiter limits abuse but is not a global spending cap.

On Windows use `pnpm.cmd` in place of `pnpm` if PowerShell blocks `.ps1` scripts.

```sh
pnpm exec wrangler login
pnpm build
pnpm check:cloudflare
pnpm deploy:cloudflare
```

The deploy command uses **`dist/server/wrangler.json`**, generated by the production build, to upload the complete Worker and its static assets. Do not deploy the source `wrangler.json` directly. A successful `check:cloudflare` is a dry run, not a live deployment.

For CI, add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as GitHub environment secrets for `cloudflare-production`. Scope the token to the intended Cloudflare account with Workers Scripts write permission. Manually run **Deploy Cloudflare Worker** in Actions. No Cloudflare authentication or account-specific secrets are committed.

## Server-only AI credentials

The Worker works without an OpenAI key. To enable paid AI after deploying it, use Cloudflare's secret store:

```sh
pnpm exec wrangler secret put OPENAI_API_KEY --name saturn
```

Enter the key at the CLI prompt; do not paste it into source, a public Actions variable, or this document. `OPENAI_MODEL` is a nonsecret Worker variable (default `gpt-5`). For local Worker testing, an ignored `.dev.vars` file can contain the key and optional model; pass it explicitly with `pnpm start --env-file .dev.vars`. Local AI calls also require the local rate-limit binding and a client-IP header. Built-in replies remain available when either is missing.

`server/affirmation.ts` reads credentials only from Worker bindings through `app/api/affirmation/route.ts`. It limits JSON bodies to 2 KiB and questions to 240 characters, rejects unapproved browser origins, handles preflight, avoids caching, and falls back without exposing provider errors. Paid calls require a working rate-limit binding. The Pages build rejects server imports, exposes no environment variables implicitly, and scans all static output for server API material and credential values. CI supplies a fake credential canary to verify this separation.

The production API provider has not been tested with a real key. Tests exercise provider authorization and error behavior with an injected mock; no paid request is made during builds.

## Reproduce validation

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build:pages
pnpm build
pnpm check:cloudflare
node --experimental-strip-types scripts/check-weather.mjs
```

For HTTP smoke tests, run `pnpm preview:pages --strictPort` and `pnpm start --port 8789` in separate terminals, then `node scripts/check-production.mjs`. Override `PAGES_URL` and `WORKER_URL` for other locations. Set `SKIP_WORKER=1` to check just the deployed Pages site. The Worker smoke test expects the keyless built-in response.

Automated storage tests use the Web Storage API in separate Node processes to verify saved tasks, scheduling, completion, and mood survive a restart. They also cover corrupt data, denied reads, and quota errors. Weather tests reject missing or nonfinite values; the live check exercises real geocoding and forecast parsing. These code and HTTP checks do not constitute an interactive browser UI test.

Reference: [GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Cloudflare secrets](https://developers.cloudflare.com/workers/vite-plugin/reference/secrets/).
